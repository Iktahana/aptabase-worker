# Privacy and reliability

The Worker stores SDK session IDs, event names, supplied system and custom properties, and the Cloudflare country, region name, and region code. Session IDs remain opaque strings. It does not store raw IP addresses or User-Agent headers, parse browser User-Agent strings, generate fingerprints, or infer missing OS information. Clients must avoid personal data in arbitrary properties, event names, and extra system fields; these are retained as supplied.

Keys are public SDK routing identifiers. CORS controls browsers and is not an authentication or abuse-prevention mechanism. Built-in IP request limits and per-app monthly event quotas reduce abuse; they cannot authenticate events. Cloudflare protections can supplement them.

Application logs contain received/submitted/dropped event counts and fixed reason codes, never payloads, keys, exception messages, or request headers. Platform logs and account request metadata are managed by Cloudflare and need separate operational review. Observability head sampling is configured at 0.1.

Analytics Engine writes are non-blocking and do not acknowledge durable storage. A 200 response means submission, not confirmed persistence. Sampling and platform retention apply. Network and server failures can lead SDKs to retry and create duplicate events, including already submitted entries from a partially failed batch. There is no deduplication, durable buffering, or exactly-once guarantee. Once a UTC day has closed, a scheduled job copies that day's Analytics Engine points into a private R2 bucket as JSON lines. The copy contains the same stored fields, not raw IP addresses or request headers. A failed day is retried once on the next run. Sampling still applies, so the bucket is not a complete copy of every accepted request.

Rate limiting reads Cloudflare’s `CF-Connecting-IP` header transiently. A missing or unparseable address is rejected with 429 and does not create a counter. Object names use a SHA-256 digest of the UTC date and either the full IPv4 address or the IPv6 /64 prefix; raw IPs are never persisted or logged. These digests are pseudonymous, not guaranteed anonymous. Idle rate counters are deleted by an alarm scheduled 60 seconds after the latest request (alarm execution may be delayed). Monthly counters retain only the current month and reserved count per stable app ID. Counters are separate from analytics and are never used for visitor metrics.
